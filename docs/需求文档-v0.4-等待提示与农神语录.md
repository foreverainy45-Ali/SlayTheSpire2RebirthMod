# SeedRestart v0.4 等待提示与农神语录需求文档

文档状态：待用户审核，未进入实现  
目标版本：v0.4.0 public-beta  
适配基线：《杀戮尖塔 2》public-beta v0.113.1、JmcModLib 1.10.0  
日期：2026-11-16

## 1. 背景与目标

v0.3.0 在重开切换阶段由单人和多人共用加载提示，因此单人模式也可能显示“等待所有玩家加载”，与实际状态不符。同时，等待状态使用 MOD 自绘的纯文本遮罩，与游戏原生弹窗风格不一致。

v0.4.0 对等待阶段的界面进行以下调整：

1. 单人模式只描述本机资源加载，不出现“其他玩家”“所有玩家”“全员”等多人措辞。
2. 重开等待状态使用游戏原生风格的模态提示框展示，不再仅以自绘文字面板呈现。
3. 每次进入重开等待阶段时，随机展示一条“菜农来辣”经典语录，缓解等待过程的枯燥感。

本需求只调整等待阶段的显示和文案，不改变失败结算、种子规则、多人投票、会话复用、QuickSL 协调及各模式重开逻辑。

## 2. 范围

### 2.1 本版包含

- Standard、Daily、Blitz 的单人重开等待提示。
- Standard、Daily、Blitz 的多人重开等待提示。
- 等待提示框的原生风格展示、状态更新和自动关闭。
- 每轮重开随机语录的选择与展示。
- 原生提示框不可用时的安全降级。
- QuickSL 共存及弹窗生命周期回归测试。

### 2.2 本版不包含

- 不改变首次确认框和多人同意/拒绝的业务规则。
- 不增加游戏内语录开关或语录编辑器；允许直接编辑发布包中的 JSON 语录配置。
- 不联网获取语录，不读取 B 站页面，也不上传任何玩家数据。
- 不为语录增加配音、图片、视频或外部链接。
- 不改变游戏种子、地图、奖励或其他随机流程。
- 不处理默认公开分支适配；仍以 public-beta v0.113.1 为本版目标。

## 3. 等待状态文案

等待提示必须根据单人/多人和当前阶段区分，不得用同一条多人文案覆盖所有场景。

| 阶段 | 单人提示 | 多人提示 |
| --- | --- | --- |
| 提交前安全准备 | 正在准备新局，请稍候… | 正在准备新局，等待安全切换… |
| 创建 Standard / Blitz 新局 | 正在创建新种子对局… | 正在创建新种子对局… |
| 创建 Daily 新局 | 正在重建每日挑战… | 正在重建每日挑战… |
| 加载新局资源 | 正在加载新局资源… | 正在进入新局，等待其他玩家加载… |
| 已完成 | 关闭提示框并恢复游戏 | 全员就绪后关闭提示框并恢复游戏 |

硬性文案约束：

- 单人流程中不得出现“其他玩家”“所有玩家”“全员”“队友”等词语。
- 单人加载阶段的核心文案使用“正在加载新局资源…”，不暗示存在网络同步等待。
- 多人投票阶段仍可显示玩家同意/等待状态；本条不属于资源加载提示。
- 多人已提交后的等待提示可以描述其他玩家加载，但不得把尚未投票误写为正在加载。
- Daily 仍应明确是重建同一当日挑战，不得显示“创建新种子”。

## 4. 原生风格等待提示框

### 4.1 展示方案

重开进入准备/加载状态时，使用 JmcModLib 提供的 `JmcReportPopup`。该组件通过游戏模态容器显示，并提供可动态更新标题、正文和状态的句柄，符合本需求的持续等待场景。

建议布局：

- 标题：`Rebirth · 快速重开`
- 正文第一部分：当前阶段文案。
- 正文第二部分：本轮随机语录。
- 底部状态：`请稍候`，或多人场景下显示当前同步进度。
- 背景：启用游戏原生深色模态遮罩。
- 等待过程中不提供会导致已提交流程中断的关闭按钮。
- 已提交后不允许通过 Escape 关闭提示框；流程完成、取消或失败时由 MOD 主动关闭。

示例：

```text
Rebirth · 快速重开

正在加载新局资源…

农神语录：删牌大于一切

请稍候
```

### 4.2 生命周期

1. 用户确认单人重开，或多人全票通过并进入准备阶段后，打开一个等待提示框。
2. 同一轮重开只允许存在一个等待提示框；阶段变化时更新原提示框，不重复创建、闪烁或叠加。
3. 成功进入新局并恢复输入后自动关闭。
4. 提交前取消、超时或预检失败时自动关闭，并按现有规则返回原局。
5. 提交后发生同步失败时关闭等待框，再显示明确的失败提示；恢复文件和日志规则保持不变。
6. 场景切换、控制器销毁或 MOD 卸载清理时必须释放弹窗句柄，不能残留不可关闭的遮罩。

### 4.3 弹窗冲突与降级

- 首次确认框关闭后才能打开等待框，不能与确认框重叠。
- 不抢占 QuickSL 或其他 MOD 已打开的原生模态窗口。
- 在支持的 public-beta 环境中，正常流程必须成功使用原生风格提示框。
- 如果原生模态容器暂时不可用，应记录原因并安全降级到现有 `RestartUi` 遮罩，保证流程不会卡死；降级界面仍须使用正确的单人/多人文案并显示语录。
- 降级仅是异常保护，不作为本版正常视觉验收的通过条件。

## 5. 随机语录

### 5.1 首版语录池

用户已审核选定 20 条语录，最终文本以发布包中的 `SeedRestart.quotes.cfg`（内容为 JSON 格式）为准。配置文件允许用户增删语录，修改后重新启动游戏生效；DLL 不硬编码正式语录池。使用 `.cfg` 扩展名是为了避免游戏将目录内的普通 `.json` 文件误识别为 Mod 清单。默认配置包含 Q01、Q02、Q03、Q06、Q07、Q11、Q14、Q15、Q17、Q18、Q20、Q21、Q22，以及 B02、B05、B06、B07、B10、B14、B15；其中 Q18 改为“我说删牌大于一切有没有懂的”，Q20 改为“体验过双飞身踢打无实体天罚吗？”。完整清单与出处等级见《候选语录-菜农来辣.md》。

显示格式统一为：`农神语录：{语录正文}`。

### 5.2 随机规则

- 每次成功进入准备/加载流程时，从语录池等概率选择一条。
- 一轮重开只选择一次；后续状态刷新沿用同一条，避免文字不断跳变。
- 单机连续重开时，在语录池大于一条的前提下，建议避免与本机上一轮立即重复。
- 多人各端可在本地独立选择，无需通过网络同步相同语录。
- 语录随机源必须与游戏运行随机数完全隔离，不得调用或推进 `RunState`、地图、奖励或种子相关 RNG。
- 语录不写入对局历史、存档、恢复文件或网络协议，只允许写入调试日志中的语录索引；默认不记录完整语录文本。

### 5.3 文本与归属

- 界面称呼使用用户指定的“菜农来辣”和“农神语录”。
- 创意工坊说明中如新增致谢，应写明“灵感与等待语录致意 B 站 UP 主‘菜农来辣’”，不得表述为官方合作、授权背书或共同开发。
- 本版不使用对方头像、视频画面、音频或其他素材。

## 6. 与现有功能的兼容要求

1. Standard：仍写入失败并切换新种子。
2. Daily：仍写入失败，保留当日固定种子、时间、幕列表及修正项。
3. Blitz：仍写入失败并切换新种子。
4. 多人投票必须继续要求原成员全员同意；语录和提示框不能参与网络一致性判断。
5. QuickSL 的按钮、快捷键、确认框、审批、加载及存档行为保持不变。
6. QuickSL 忙碌时仍阻止换种；换种尚未提交时发起 QuickSL，仍按现有规则取消换种。
7. 等待弹窗关闭后，键盘、鼠标和手柄焦点必须正常回到游戏，不得造成暂停菜单或 QuickSL 无法操作。
8. 不增加对 QuickSL 的编译或运行依赖；仍只依赖 JmcModLib。

## 7. 验收标准

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| U01 | 单人 Standard 重开 | 原生风格提示框显示“正在加载新局资源…”，不出现任何多人等待措辞 |
| U02 | 单人 Daily 重开 | 显示“正在重建每日挑战…”及资源加载提示，不显示“创建新种子”或等待其他玩家 |
| U03 | 单人 Blitz 重开 | 显示创建新种子及资源加载提示，不出现多人等待措辞 |
| U04 | 双人由客户端发起并通过 | 投票状态与加载状态区分；提交后可显示等待其他玩家加载，双方最终关闭提示框进入同一新局 |
| U05 | 多人拒绝、取消或超时 | 不写失败、不重开；提示框正确关闭，无残留遮罩和焦点丢失 |
| U06 | 连续重开 10 次 | 每轮只显示一条语录；阶段更新时语录不变；正常情况下相邻两轮不重复 |
| U07 | 检查默认 20 条语录 | 均可被随机选中，文字完整，没有截断、乱码或超出弹窗边界 |
| U08 | 相同种子与配置对照测试 | 启用语录前后地图、奖励等游戏随机结果一致，证明未消耗游戏 RNG |
| U09 | 16:9、16:10 及常用窗口尺寸 | 弹窗居中、正文自动换行，最长语录可读，按钮/状态不溢出 |
| U10 | 键鼠与手柄操作 | 等待期间不能误关已提交流程；完成或失败后焦点恢复正常 |
| U11 | 原生弹窗临时不可用 | 记录降级原因并使用备用遮罩完成或安全取消，不发生死锁 |
| U12 | 单人及多人重开后立即 QuickSL | QuickSL 正常显示自己的界面并完成加载，不受残留模态弹窗影响 |
| U13 | 发布构建检查 | 发布 DLL 不包含测试探针；版本、说明和工坊更新记录与本需求一致 |

## 8. 实施边界与审核项

审核通过后再进行代码修改。计划实施顺序：

1. 把等待文案生成逻辑按单人/多人、Daily/非 Daily、准备/创建/加载阶段拆分。
2. 增加独立语录池和不消耗游戏 RNG 的本地选择器。
3. 使用 `JmcReportPopup` 替换正常流程中的自绘等待层，并保留异常降级路径。
4. 完成单人三种模式测试，再进行双人投票、拒绝、加载和 QuickSL 回归。
5. 用户实机确认视觉后，才构建并上传下一版创意工坊。

需要用户审核确认的默认设计：

- 等待框标题使用“Rebirth · 快速重开”。
- 语录前缀使用“农神语录：”。
- 同一本机相邻两轮尽量不重复，多人不强制显示同一句。
- 等待阶段不可手动关闭，完成/取消/失败时自动关闭。
- 首版发布 20 条默认语录，不提供游戏内设置开关，但允许编辑外部 JSON 配置。
