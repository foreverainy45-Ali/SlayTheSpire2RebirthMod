# SeedRestart / 快速换种重开

结束当前对局并写入失败记录，保留每位玩家的角色和升阶，以新随机种子回到第一幕涅奥。支持单人及 2–4 人联机；多人由任意一人请求，其他玩家全部同意后在原联机会话内重开。

当前版本：**0.4.1 public-beta 测试版**。目前只适配 Windows public-beta **v0.113.1**；默认公开分支暂不启用，等待 beta 版实机确认后再适配。

## 安装与使用

1. 安装并启用 **JmcModLib 1.10.0 或更高兼容版本**。
2. 将发布包中的 `SeedRestart` 文件夹放入游戏安装目录的 `mods` 文件夹并启用；多人所有玩家必须使用相同版本。
3. 对局中按 Esc，在暂停菜单点击“换种重开”。
4. 单人确认后执行；多人由发起人确认请求，其他玩家分别在原生弹窗中同意。全员同意后，每位玩家的旧局均记为失败并同步重开；任意一人拒绝或 30 秒未全员同意则取消。

重开准备和资源加载期间使用与游戏确认框相同的原生石板提示框，并随机显示一条语录。加载状态显示在中央，语录只显示正文并在框内底部居中。单人只显示本机资源加载状态，不会提示等待其他玩家；多人提交后会显示同步等待状态。语录来自安装目录中的 `SeedRestart.quotes.cfg`（内容为 JSON 格式），可自行增删，修改后重新启动游戏生效；语录随机不会消耗游戏对局 RNG。

版本规则：修复、兼容和纯界面调整递增补丁号（例如 `0.4.0` → `0.4.1`）；新增或改变功能时才递增次版本号（例如 `0.4.x` → `0.5.0`）。

模式规则：

- Standard：保留角色、升阶和受支持的原生修正项，使用新随机种子回到第一幕涅奥。
- Daily：写入非放弃的失败历史，保留当日固定种子、当日时间、幕列表、修正项、角色与难度，回到第一幕涅奥。游戏原生每日模式不会把这次失败计入普通角色的总局数/失败数。
- Blitz：写入失败记录并增加相应统计，保留角色与 Blitz 升阶，使用新随机种子重新开始。

安装结构：

```text
Slay the Spire 2/
  mods/
    SeedRestart/
      SeedRestart.dll
      SeedRestart.json
      SeedRestart.quotes.cfg
```

JmcModLib 是 0.2.0 起的界面依赖，用于提供与 QuickSL 一致的暂停菜单入口和游戏原生确认框。不需要安装 QuickSL 或 BaseLib；已有 QuickSL 的用户继续保留其原有前置。

## 与现有快速 SL 共存

- 不替换 QuickSL 的任何文件、设置、快捷键或按钮。本 Mod 默认不绑定快捷键。
- 已验证 QuickSL **1.9.0**、JmcModLib **1.10.0**、BetterSaveSlots **1.2.2** 同时安装的组合。
- QuickSL 正在审批/加载时不能发起换种；换种仍在投票或准备时，发起 QuickSL 会取消尚未提交的换种，让 SL 正常继续。
- 全员已批准、正在实际切换新局时，两种加载操作暂时互斥；新局就绪后 QuickSL 即可使用，读取的是新局存档。
- 检测到尚未适配的 QuickSL 版本时，本 Mod 停用换种功能并提示，不要求关闭或更换 QuickSL。

## 保留与重置

保留：房主、联机连接、玩家身份、实际使用的角色、升阶、受支持的原生自定义修正项。

重置：种子、地图、战斗、卡组、生命、金币、遗物、药水和奖励选择，均按正常新局规则初始化；涅奥奖励需要重新选择。每位玩家的旧局都写为失败（不是放弃），失败数、总局数和历史记录正常增加；新局拥有正常自动存档。

种子不同不保证所有奖励或地图内容都不同。

## 支持范围与限制

- 目前支持 Standard、Daily 和 Blitz。Dread 尚未开放。
- 原生角色为首版验证范围；其他内容 Mod、Mod 角色及复杂修正项未做全面组合测试。
- Standard 已完成单人及 2/3/4 人隔离测试；Daily 与 Blitz 已完成单人、双人原生确认/拒绝、失败历史、连接保持和重开后 QuickSL 测试，详见 [验证记录](docs/验证记录.md)。Steam 公网、异常丢包和断线恢复仍需实测。
- 不包含快速 SL、同种子重开、回合撤销、节点回溯、自动刷种或定向涅奥奖励。
- 纯动画/动作执行中会等待安全边界；超过准备时限则取消。复杂的待选卡牌、商店及第三方弹窗场景仍需进一步验收。
- 自动测试已确认 JmcModLib 注册了暂停菜单按钮，并驱动原生确认框的取消/确认信号；最终鼠标布局与视觉仍需在正常窗口中人工验收。

## 故障恢复

重开前保留本次操作的恢复副本，存放在游戏用户数据目录的：

```text
mod_configs/SeedRestart/recovery/
```

多人房主副本优先作为恢复依据，客户端副本是辅助现场记录。成功写入新局后自动清理副本。提交后发生故障时保留副本并停止继续操作；此时保留日志与副本，退出测试并排查。此机制不是用户可选的快速 SL 功能。

## 构建与验证

需要 .NET 9 SDK、本机游戏的 `sts2.dll`、`GodotSharp.dll`、`0Harmony.dll`，以及 JmcModLib 1.10.0 的 `JmcModLib.Runtime.dll` 编译引用。

```powershell
.\build.ps1
# 游戏在其他位置：
.\build.ps1 -Sts2Dir 'D:\SteamLibrary\steamapps\common\Slay the Spire 2'
```

构建结果在 `dist/SeedRestart`。项目不从 NuGet 拉取运行依赖；引用的游戏库不会被复制进发布包。

`tools/Prepare-RuntimeTest.ps1`、`Start-RuntimeTest.ps1` 和 `Test-*Cycles.ps1` 为开发测试工具，仅对隔离副本使用。测试构建通过 `RuntimeProbe=true` 开启驱动；正常发布 DLL 不包含驱动，也不会自动同意任何人的请求。测试中的 QuickSL 确认由测试专用提供器自动回应，其原有网络审批/加载流程仍实际运行。

本项目仅通过已安装程序集研究接口和生命周期；发布包不包含游戏资产、其他 Mod 的程序集或其反编译源码。
